### ADR-011 — Publish state machine: additive `PublishAttempt`, intent ≠ published
**2026-07-15.** Mevcut `PublishLog` prepared için ZORLANMAZ (success default true, publishedAt now, queueItemId yok → günlük limit sorgularını kirletir). Additive `PublishAttempt` modeli (prepared|succeeded|failed, adapter, idempotencyKey, contentHash, readinessPolicyVersion, readinessSnapshotJson, externalId, `@@unique([accountId,adapter,idempotencyKey])`). Intent = yalnız `PublishAttempt(prepared)`; PublishLog+PublishedPost yalnız manuel "Paylaşıldı" onayı VEYA API başarısı (aynı transaction). Ağ çağrısı transaction dışında; idempotent reconciliation. **Gerekçe:** kullanıcı düzeltmesi — intent açmak yayın başarısı değildir; PublishLog modeli prepared'a uygun değil. **Kanıt:** `prisma/schema.prisma` PublishLog (success bool, publishedAt now).

### ADR-012 — Doğrulama ≠ fact-check: 5 durum

"fact-check tamamlandı" dili yalnız `verified`. **Gerekçe:** kullanıcı düzeltmesi — kaynak varlığı ≠ doğruluk kontrolü.

### ADR-013 — Auth: `proxy.ts` + ayrı hash+secret + HMAC'li kalıcı throttling
**2026-07-15.** Next 16 middleware = `proxy.ts` (yerel doc doğrulandı). `ACCESS_PASSWORD_HASH` (scrypt) ≠ `SESSION_SECRET` (cookie HMAC). Throttling: DB-backed atomik sayaç, ham IP saklanmaz (`HMAC(ip, SESSION_SECRET)`), güvenilir Vercel forwarding zincirinden IP, TTL+sweep, IP-sınır + global saldırı penceresi, başarıda sıfırlama. Prod'da env eksikse fail-closed. sameOriginGuard CSRF olarak kalır — **same-origin ≠ authentication**. **Gerekçe:** master prompt P0 + kullanıcı sertleştirme düzeltmesi; canlı denetim auth'suz erişimi doğruladı. **Kanıt:** `node_modules/next/dist/docs/.../proxy.md`; `shots/cemos-rebuild/baseline/`.
**[USER-ACTION]** Vercel Firewall/WAF (rate-limit) operasyonel öneri — kod-üstü ek katman.

### ADR-033 — Faz 2D: Doğrudan thread üretimi ve dürüst thread yayın sözleşmesi
**2026-07-16 (kullanıcı Phase 2D onayı; kod öncesi gerçek DB audit'i zorunluydu).**

**Kod-öncesi audit bulgusu (Neon, read-only, `scripts/audit-thread-readiness.ts`):** 60 QueueItem içinde 13 thread taslağı — TAMAMI `mode=thread` + `draftType=TWEET` + `threadSegments=NULL` + `status=new`; readiness draftType'a baktığı için **12'si tek-tweet gibi yanlışlıkla "ready"** görünüyordu (894 karaktere kadar yapısız metin). Etiketli kalibrasyon örneği: 0 pozitif (published/approved) + 0 negatif (rejected) judged thread → **calibrationStatus = insufficient_sample**.

**Canonical authority (bağlayıcı):** `threadSegments` thread'in canonical publication payload'ıdır; array sırası = thread sırası; her segment trim'li ve boş değildir; thread ≥2 segment taşır (ürün hedefi 5–8; şema güvenlik tavanı 25). `QueueItem.content` yalnız backward-compatible birleşik temsildir — `joinThreadSegments` ("\n\n") ile HER ZAMAN segmentlerden türetilir. Non-thread taslakta threadSegments null. Metindeki "1/" numaralandırma yapısal kanıt DEĞİLDİR. **Segment sınırı tek primitive'dir:** `effectiveThreadSegmentLimit = min(280, account.maxChars)` — UI/readiness/generation/schedule/publish aynı fonksiyonu kullanır; UI'daki ayrı `SEGMENT_MAX=280` literali KALDIRILDI. Thread tespiti mode-farkındalıdır: `isThreadDraft(draftType, mode)` — audit'teki uyumsuz sınıf artık tek tweet gibi değerlendirilemez. **Yeni QueueItem thread kolonu EKLENMEDİ** (alan Faz 1C'den beri var; ADR-010 sözleşmesi korunur); bu pass'te şema migration'ı YOK.

**Writer strict schema:** `WRITER_RESPONSE_SCHEMA` (strict json_schema; degrade zinciri json_object'e düşer) `threadSegments` alanını taşır. Çağıranın format niyeti writer'a AÇIKÇA gider (`RequestedDraftFormat`: thread zorunlu / tweet yasak / auto). Explicit thread isteğinde geçerli segment yoksa BİR repair retry; hâlâ yoksa **judge'a harcama yapılmadan** typed `threadRequestUnsatisfied` → çağıran QueueItem YAZMADAN blocked döner. Sahte tek-segment/mock thread ÜRETİLMEZ (`createMockBenchmark` segment üretmez; mock + thread isteği = blocked).

**Judge provenance:** writer taslakları deterministik 0-tabanlı indeksle sunulur; judge `sourceDraftIndex` döndürür. `bindJudgeCandidates`: canonical content/mode/threadSegments/payoff WRITER adayından, skor/verdict/reason judge'dan; geçersiz indeks → birebir content eşleşmesiyle deterministik fallback; çözülemeyen aday DÜŞER; aynı taslak iki indeksle duplicate EDİLEMEZ. Fast/risk_based/deadline/judge-empty yolları segmentleri korur. Eski persist candidatesJson (alan yok) okunmaya devam eder.

**Final editor parity:** thread kazananında final editor AÇIKÇA atlanır (`finalEditor="skipped:thread_segment_contract"`, trace'te görünür) — birleşik metni yeniden yazıp segmentleri stale bırakma sınıfı kapatıldı. Non-thread davranış değişmedi.

Thread lint'i deterministik ve SEGMENT bazlıdır (`half_sentence_end`/`below_min_chars` segmentte uygulanmaz; segment başına ücretli LLM lint ÇAĞRILMAZ — thread'de LLM mikro-pass bilinçli atlanır). Format niyeti: draftType=THREAD / mode=thread / Source.mode=thread → thread ZORUNLU; çağıranın bilinen non-thread modu → explicit TWEET kilidi (thread kazanan uzun içerik TWEET diye persist EDİLMEZ; thread-dışı aday yoksa dürüst `no_non_thread_candidate`); körlemesine `draftType:"TWEET"` default'u = auto (geçerli thread kazanan → THREAD'e yükseltilir, `auto_thread_winner`; geçersiz thread kazanan → görünür non-thread fallback). Opportunity handoff akışı bilinçli explicit-TWEET kaldı (thread kazananda non-thread aday seçer, yoksa dürüst hata). Atomize: "thread" packageRole YALNIZ geçerli segmentli adaya (THREAD+segments persist); segmentsiz aday thread etiketi alamaz; reused candidate maliyeti 0 kalır.

**Readiness parity (policy 1.0.0→1.1.0-provisional):** `ReadinessInput.accountHandle` string — bilinmeyen hesap grafikcem'e MAP EDİLMEZ; seed'li politikalar (emoji) yalnız EXACT handle eşleşmesinde.
